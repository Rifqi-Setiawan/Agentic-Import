# Audit objektif ImporJaga

Tanggal 4 November 2026, WIB. Sumber: snapshot VPS `/srv/hermes-control/services/agentic-import` pada commit `801ffab2a2aedfb404fe2dd967cec62101dfad8c`, spesifikasi MVP v1.1, laporan evaluasi, kode frontend/backend, serta pemeriksaan baca layanan live. Working tree bersih saat diambil. GitHub main saat diperiksa berada di `176212d0738eed6c5bc0db4025e6f61967bc8286`, sehingga dua commit terakhir VPS belum ada di main remote.

## Verdict

**Belum memenuhi kontrak MVP operasional dan belum siap direkomendasikan untuk penilaian lomba dengan klaim sekarang.** Yang sudah ada: UI demo online, login dan pembacaan data, struktur modul, model database, beberapa fungsi domain nyata, serta kerangka graph dan worker. Yang belum terwujud pada snapshot: analisis invoice oleh agent live secara menyeluruh, pengiriman SMTP nyata, watcher generik, dan bukti evaluasi yang dapat direproduksi.

Penilaian ini tidak menyimpulkan niat pengembang atau menuduh angka sengaja dipalsukan. Kesimpulan dibatasi pada perilaku kode dan bukti yang tersedia. Banyak teks hasil saat ini menyerupai keluaran nyata, meski proses pembentuknya belum diimplementasikan.

## Pemeriksaan yang dijalankan

- Membaca README/PROGRESS, seluruh area agent/worker/API dan komponen frontend terkait, serta tes dan laporan evaluasi; dua penelaah independen memeriksa agent dan keamanan/API.
- Protected suite pada VPS: **20 passed in 0.28s**. Ruff: **All checks passed**.
- Uji graph terisolasi tanpa dokumen/item: menghasilkan **13 langkah hasil**, tetapi `items=[]`, `documents=[]`, outcome waiting_external. Tidak ada panggilan model atau perubahan produksi dalam uji ini.
- Hitung ulang 60 baris laporan eval: HS8 exact 57/60, HS6 exact 57/60, expected dalam top_candidates 54/60. Tiga flag hs8_match true bertentangan dengan string prediksi.
- HTTP live: login staf 200; daftar kiriman 200; `/api/v1/dashboard/summary` 404; `/api/v1/admin/company-settings` 404. Health UP meski heartbeat yang dikembalikan sudah sekitar empat jam lebih lama daripada timestamp respons.
- Browser live menampilkan empat kiriman. Contohnya CIF dalam rupiah disajikan sebagai `USD 78.940.712,5`, sesuai pencampuran field di API/UI.
- Penelaah keamanan mereproduksi tiga endpoint dengan cursor fixture tanpa koneksi DB: PIB asing dikembalikan; item classified tanpa dokumen dapat submitted; staf dapat modify review ke kode non-HS dan mendapat memory_recorded true.
- Tidak menjalankan full integration suite: tes itu melakukan reset, simulasi, jawaban, persetujuan, dan analyze menggunakan konfigurasi database aplikasi tanpa isolasi.

## Temuan prioritas

P1 = harus selesai sebelum menyatakan MVP siap dinilai/publik. P2 = masalah signifikan yang perlu diselesaikan sebelum mengandalkan hasil atau operasional. Nomor baris merujuk snapshot commit di atas.

### F01 — P1: graph menghasilkan narasi sukses tanpa mengerjakan analisis

Lokasi: `src/agent/graph.py:27–87`, `src/agent/llm.py:3`, `src/worker/main.py:82–92`.

Node ekstraksi, rencana, klasifikasi, pemeriksaan, lartas, pungutan, email, dan PIB hanya menambahkan string tetap. Worker memberi graph daftar item dan dokumen kosong. Modul llm hanya mengatur anggaran token, bukan klien model. Compile graph tanpa checkpointer.

Dampak: invoice baru tidak diubah menjadi hasil berdasarkan isinya. Klaim ReAct, kritik model berbeda, pencarian bukti, pemulihan checkpoint, dan otonomi belum dibuktikan oleh implementasi ini.

Perbaikan: satu alur vertikal nyata PDF → ekstraksi → retrieval → model/tool → validasi sumber → simpan hasil → readiness. Langkah trace hanya ditulis sesudah pekerjaan yang sesuai benar-benar terjadi. Setelah alur pertama jalan, lanjutkan klarifikasi, verifier, memori, serta watcher.

### F02 — P1: evaluasi tidak konsisten dan tidak dapat dijalankan ulang

Lokasi: `reports/eval_report_agent.json:6–10`, README bagian benchmark/evaluasi.

Summary menyebut HS8 top-1 100%, HS6 95%, top-3 90%. Penghitungan ulang menunjukkan HS8 95%, HS6 95%, dan expected dalam daftar kandidat 90%. Tiga flag exact-match salah. Perintah README menunjuk `backend/app/eval/eval_hs.py` yang tidak ada di snapshot. Tidak ada runner evaluasi ter-track.

Dampak: angka 100% dan klaim keunggulan agent bukan bukti yang layak dipakai proposal. Angka 95% hasil hitung ulang pun hanya konsistensi berkas; bukan pengesahan bahwa agent live menghasilkan prediksinya.

Perbaikan: tarik klaim angka sampai runner live tersedia; generate seluruh summary dari prediksi, jangan menyimpan flag yang dapat menyimpang. Simpan commit, versi dataset/prompt/model, run ID, token, sumber jawaban dan log eksekusi. Uji dataset terpisah dari pengembangan prompt.

### F03 — P1: data PIB dapat terbaca antar-perusahaan

Lokasi: `src/api/shipments.py:406–446`.

Endpoint PIB membaca shipment berdasarkan ID tanpa memeriksa company_id. Mengembalikan nama importir, NPWP, pemasok dan pungutan. ID integer dapat ditebak. Fixture asing berhasil dikembalikan dalam uji endpoint terisolasi. DB live saat audit hanya mempunyai kiriman company 1; eksploit lintas dua tenant live tidak dilakukan.

Perbaikan: scope query pada company_id pengguna sebelum membaca data turunan; uji seluruh resource termasuk PIB, file, SSE, pesan dan memori dengan dua perusahaan nyata pada DB tes.

### F04 — P1: role hanya ada sebagai identitas, belum ditegakkan di mutasi API

Lokasi: `src/api/reviews.py:63–81`, `src/api/admin_routes.py:11`, `src/api/regulations.py:47–56`, `src/api/deps.py:26–48`.

Dependency memeriksa token tetapi endpoint tidak memeriksa role. Staf dapat memanggil keputusan reviewer, simulasi, dan reset. Uji terisolasi membuktikan staf diterima pada modify review.

Perbaikan: dependency require_roles pada setiap endpoint; negative tests 403 per role. Menu UI tidak menggantikan kontrol backend.

### F05 — P1: readiness pengajuan mengabaikan penghalang penting

Lokasi: `src/api/shipments.py:175–183`, `213–248`.

Detail mengirim has_open_reviews=False dan has_pending_jobs=False. Pengajuan menerima status classified meski belum disetujui; hanya membaca dokumen yang sudah ada, tidak membaca persyaratan checklist yang belum diunggah, review, jobs atau coverage. Fixture satu item classified dan nol dokumen berhasil menghasilkan submitted.

Perbaikan: satu service evaluasi dari query state lengkap, dipakai detail dan aksi pengajuan dalam transaksi/kunci yang sama. Missing/pending requirement, persetujuan belum ada, coverage unknown dan job aktif harus menghalangi.

### F06 — P1: UI menampilkan keberhasilan dan hasil yang tidak berasal dari operasi/data

Lokasi: `frontend/src/App.tsx:139–147`, `497–501`, `555–558`, `579–601`, `634` dan seterusnya.

Create shipment hanya memanggil GET daftar kiriman lalu menyatakan berhasil. Tab pungutan memakai angka literal tetap. HS kosong diganti 8481.80.90, confidence kosong/0 diganti 92%, trace berisi kartu statis, dan belum ada EventSource di App. Tidak ada input upload yang menghubungkan uploadDocument pada UI tersebut. Data hilang terlihat seperti hasil terverifikasi.

Dampak: juri yang mencoba kiriman/berkas sendiri tidak mengalami pipeline yang diklaim; hasil antar-kiriman dapat terlihat sama. PIB juga menggunakan data tetap dan label “Draf Elektronik Resmi”, bertentangan dengan label draf prototipe.

Perbaikan: sambungkan POST create/upload dan hasil API aktual, hapus semua fallback hasil bisnis, gunakan keadaan “belum tersedia”, dan trace SSE dari run aktual. Tampilkan status error yang dapat dipulihkan.

### F07 — P1: status email terkirim tanpa pengiriman SMTP

Lokasi: `src/worker/outbox.py:33–61`.

Jalur normal mengembalikan SENT tanpa koneksi SMTP. Cabang kegagalan bergantung parameter simulate_failure. Tidak ada pengiriman nyata yang dihubungkan ke worker.

Perbaikan: outbox persisten → SMTP adapter → hasil penerimaan/error/unknown; allowlist tepat inbox tim; deduplikasi dan satu reminder. Bedakan queued, diterima SMTP, unknown, dan delivered bila benar-benar mempunyai bukti.

### F08 — P1: watcher mengubah nomor kiriman seed, bukan mencari dampak aturan

Lokasi: `src/api/regulations.py:84–104`, `src/worker/watcher.py:4`.

Simulasi langsung mengubah MKN-007 dan MKN-008. Tidak mencari item yang cocok hs_prefix, tidak menghitung perubahan kewajiban untuk kiriman baru. Hasil teks juga menyebut nomor demo tetap.

Perbaikan: simpan event aturan scoped company, cari item menurut HS dan tanggal berlaku, buat recalc/checklist/dampak/tugas. Seed adalah input skenario, bukan cabang logika produksi. Tes kiriman dengan nomor lain dan HS yang sama.

### F09 — P1: reset tidak terisolasi sesuai perusahaan pemanggil

Lokasi: `src/api/admin_routes.py:19–36`, `src/core/seed.py:35–37`.

Pemeriksaan pekerjaan memakai perusahaan pengguna, tetapi seed_data(reset=True) menghapus data company 1. Dengan tenant kedua, reset dapat memengaruhi perusahaan lain. Memperbaiki role saja tidak menyelesaikan ini.

Perbaikan: reset menerima company_id yang tervalidasi; pemeriksaan idle dan penghapusan berada pada tenant/transaksi yang sama. Pertahankan referensi dan data operasional.

### F10 — P1: reviewer dapat menyimpan kode HS sembarang

Lokasi: `src/api/reviews.py:116–139`, `src/models/entities.py:92–93`.

Modify tidak memvalidasi delapan digit/keberadaan hs_codes. Approve bahkan mempunyai fallback 84223000 jika usulan kosong. Fixture NOT-A-REAL-HS diterima dan dimasukkan ke memori. Keputusan tidak mengantrekan perhitungan ulang.

Perbaikan: validasi katalog HS dan versi, hilangkan fallback kode, beri FK/constraint, buat audit dan recalc atomik. Memori hanya berisi keputusan manusia yang sah.

### F11 — P1: validasi upload dan pemicu otomatis belum ada

Lokasi: `src/api/shipments.py:258–293`.

Seluruh bytes dibaca ke memori lalu disimpan, langsung provided. Tidak memeriksa tipe/magic bytes/ukuran/jumlah/PDF terenkripsi dan halaman. Endpoint tidak membuat job analisis atau menaikkan versi input.

Perbaikan: batasi streaming dan disk, verifikasi file, simpan status ekstraksi terpisah dari bukti kelengkapan; buat event/job dalam transaksi. Tidak mengklaim arbitrary file write karena eksploit path traversal belum dibuktikan.

### F12 — P1: worker tidak pulih dari crash dan tidak membedakan job type

Lokasi: `src/worker/main.py:28–45`, `67–124`, `src/agent/graph.py:135`.

Job committed processing tetapi pengambilan hanya queued; crash dapat meninggalkan job selamanya. j_type hanya dicetak lalu semua masuk graph yang sama. Tidak ada checkpoint persistence pada graph. Token 1250 dan biaya USD0.0020 ditulis tetap; langkah baru dimasukkan setelah invoke selesai.

Perbaikan: dispatcher per job, lease/heartbeat/reclaim, checkpointer dan idempotensi efek samping. Catat token/biaya dari respons model dan trace tiap langkah, bukan angka tetap.

### F13 — P2: health menyatakan sehat dengan heartbeat kedaluwarsa

Lokasi: `src/api/health.py:20–30`.

Health selalu UP dan mengambil heartbeat terakhir dari jobs tanpa membandingkan umur. Respons live saat audit menunjukkan heartbeat sekitar empat jam lebih lama daripada timestamp respons, tetapi status tetap UP. Tidak berarti worker pasti mati; berarti health tidak membuktikan liveness worker.

Perbaikan: heartbeat worker independen dari aktivitas job; degraded/non-200 readiness probe saat terlalu lama, dengan batas waktu jelas.

### F14 — P2: tes hijau belum membuktikan kontrak MVP; full suite berisiko mengubah demo

Lokasi: `tests/test_acceptance_protected.py:89–107`, `140–146`, `scripts/verify.sh`, `tests/test_api_integration.py`, `src/core/config.py`.

Tes A01 hanya memanggil helper akses, A02 menghitung daftar buatan, A05 membandingkan dedupe string. Endpoint/pipeline yang menyimpang masih lolos. Integrity check verify.sh hanya memeriksa keberadaan berkas, bukan hash. Integration suite memanggil reset/simulate/answer/review/analyze, dan konfigurasi env dipatok ke direktori aplikasi.

Perbaikan: fixture DB tes terisolasi dengan guard database-name; HTTP dan worker E2E untuk A01–A18, rollback/cleanup fixture, test concurrency/crash dan SMTP sandbox. Pertahankan unit tests sebagai lapisan pertama, bukan bukti acceptance menyeluruh.

## Temuan tambahan

- Memori di `src/agent/tools.py:111–129` tidak memfilter company_id dan memberi similarity tetap 0.95 berdasarkan pencarian kata pertama. Graph belum memanggilnya, sehingga jalur kebocoran melalui agent belum direproduksi; perbaiki sebelum dihubungkan.
- Token hanya didecode tanpa memeriksa user aktif/role perusahaan terkini (`src/api/deps.py:26–48`).
- Throttle berupa dictionary proses; restart menghapus counter, multi-process berbeda counter. Forwarded headers dipercaya tanpa verifikasi proxy; header Retry-After yang dipasang sebelum melempar exception tidak otomatis ikut respons exception.
- Data referensi belum mempunyai bukti memadai untuk klaim “resmi terverifikasi”: sebagian URL hanya halaman utama, ada path simulasi, dan periode kurs berlabel mingguan mencakup sebulan. Ini memerlukan audit sumber resmi terpisah; audit kode ini tidak memutuskan keabsahan hukum tiap kode/tarif.
- README badge CI adalah gambar bertuliskan Passing tanpa tautan workflow. Jumlah tes dan status PROGRESS tidak sesuai bukti terkini; Sentinel PASS belum tercatat pada PROGRESS. Audit ini bukan pengganti release gate Sentinel native.

## Yang sudah mempunyai nilai nyata

- Domain HTTPS dan API login/daftar data benar-benar dapat diakses.
- Fungsi domain terpisah, pemakaian Decimal pada kalkulator inti, parameter SQL, dan helper isolasi adalah fondasi yang dapat dilanjutkan.
- Protected unit tests dan Ruff lolos pada snapshot; struktur perusahaan/role dan beberapa tampilan data sudah tersedia.
- Pemisahan modul memberi tempat yang masuk akal untuk melengkapi implementasi, meskipun istilah Clean Architecture pada README belum menjadi bukti alur end-to-end.

## Urutan remediasi paling bernilai

1. **Kejujuran output dan pengamanan:** hapus hasil fallback/trace statis/klaim benchmark, perbaiki role, tenant PIB/reset, serta readiness. Tutup kemungkinan hasil belum valid tampak sah.
2. **Satu alur nyata:** buat kiriman → upload PDF → ekstraksi → retrieval/model → klasifikasi bersumber → simpan hasil → SSE → keputusan reviewer → pungutan/checklist/PIB. Uji dengan invoice berbeda dari seed.
3. **Otonomi:** klarifikasi subset, email sungguhan, followup, watcher untuk nomor kiriman arbitrer. Tambahkan recovery dan idempotensi di jalur yang sama.
4. **Bukti:** evaluation runner reproducible, benchmark aktual dan baseline sebanding, sumber data terverifikasi, lima demo live, Sentinel pada hash final, baru sinkronkan GitHub dan dokumentasi.

## Implikasi untuk lomba

Saat ini tampilan dapat mengenalkan konsep, tetapi belum menunjukkan agent yang melakukan pekerjaan berdasarkan input baru. Jika juri memeriksa kode, mengganti invoice, atau meminta bukti evaluasi, perbedaan klaim dan implementasi mudah terlihat. Prioritas tertinggi adalah menyelesaikan satu alur nyata yang dapat dicoba ulang dan menghasilkan bukti, bukan menambah tampilan/fitur.

Tidak diberikan skor peluang menang: guidebook asli, kualitas pesaing dan kinerja live agent belum diverifikasi. Verdict kesiapan teknis berdasarkan audit ini adalah **REQUEST CHANGES / belum siap submission dengan klaim saat ini**.

Tidak ada kode, konfigurasi deployment, isi kiriman, keputusan review, aturan, atau data demo yang diubah oleh audit. Login audit menghasilkan token dan dapat memperbarui telemetry login biasa. Pengujian endpoint sensitif dilakukan dengan fixture cursor tanpa DB; reset, pengajuan dan pengiriman email live tidak dijalankan.
